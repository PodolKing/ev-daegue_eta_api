# requirements.txt 충돌 방지 규칙

목적: `requirements.txt`에서 잦은 Git 충돌을 줄이고, 의존성 변경 이력을 일관되게 관리한다.

**통일 정책: 새 패키지는 항상 파일 맨 아래에 append한다. A-Z 재정렬·중간 삽입 금지.**

## 1) 수정 원칙
- 새 패키지는 `requirements.txt` **맨 아래 한 줄 추가**만 한다.
- 기존 줄을 알파벳순으로 끼워 넣거나, 파일 전체를 A-Z로 재정렬하지 않는다.
- 직접 타이핑으로 중간 위치를 고르지 말고, `pip install <package>` 후 버전을 확인한 뒤 맨 아래에 반영한다.
- 한 PR(또는 한 커밋)에서 의존성 변경과 대규모 기능 변경을 섞지 않는다.
- 팀 공통 파일인 만큼 불필요한 버전 업그레이드는 금지한다.

## 2) 의존성 추가/변경 절차
1. 가상환경 활성화 (예: `.venv`)
2. 패키지 설치/업데이트 (`pip install ...`)
3. `pip freeze > requirements.txt`로 **전체 덮어쓰기 금지** — 변경된(직접 추가한) 패키지만 반영
4. 새 패키지 줄은 파일 **맨 아래**에 `패키지명==버전` 형식으로 append
5. 이미 있는 패키지 버전만 올릴 때는 **해당 줄만** 수정 (위치 이동 금지)
6. 앱 실행/테스트 후 커밋

## 3) 버전 정책
- 새 패키지는 명시 버전(`==`)으로 고정한다.
- 이미 있는 패키지를 올릴 때는 이유를 PR 설명에 적는다.
- 트랜지티브 의존성(직접 import하지 않는 패키지)을 임의로 삭제하지 않는다.

## 4) 머지 충돌 해결 규칙
- `<<<<<<<`, `=======`, `>>>>>>>`가 보이면 즉시 수동 정리한다.
- 같은 패키지가 양쪽 브랜치에서 다른 버전이면:
  - 기능 호환성 확인
  - 더 높은 버전을 무조건 선택하지 말고 실제 동작 기준으로 결정
- 충돌 해결 후 **중복 라인**이 없는지 최종 확인한다. (정렬 여부는 검사하지 않음)

## 5) 금지 사항
- 전체 A-Z 재정렬, 중간 삽입으로 기존 줄 순서를 바꾸지 않는다.
- `requirements_BACKUP_*`, `requirements_LOCAL_*`, `requirements_REMOTE_*` 같은 임시 파일을 커밋하지 않는다.
- 개인 로컬 테스트용 패키지를 공용 `requirements.txt`에 추가하지 않는다.

## 6) 권장 체크리스트 (커밋 전)
- [ ] 새 패키지가 파일 맨 아래에 append 되었는가?
- [ ] 기존 줄 순서를 바꾸지 않았는가?
- [ ] 동일 패키지 중복 라인이 없는가?
- [ ] 충돌 마커가 제거되었는가?
- [ ] 변경 이유를 설명할 수 있는가?
